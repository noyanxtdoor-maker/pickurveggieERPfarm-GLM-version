# Development Rules

## Rule 1 — Do not rewrite approved modules

Existing approved designs must be preserved.

Only improve missing functionality.

---

## Rule 2 — Analyze before changing

Before any modification:

- Study existing files
- Identify dependencies
- Explain risks

---

## Rule 3 — Build small controlled changes

Avoid massive rewrites.

Use modular improvements.

---

## Rule 4 — Protect accounting integrity

No transaction may bypass the financial ledger.

Every movement must be auditable.

---

## Rule 5 — Protect inventory traceability

The system must always know:

- Where a product came from
- Where it moved
- Who moved it
- When it moved
- What it cost

---

## Rule 6 — Offline-first design

The ERP must continue operating with unstable island internet.

Sync safely when connection returns.
