# 20.03 User Accounts, Roles and Permissions

## Purpose

This document defines the identity, access control, roles, permissions, and branch assignments of all users inside PickUrVeggie ERP V3.

The system follows a Branch-Aware Role-Based Access Control (BA-RBAC) model.

A user's authority depends on:

- Company membership
- Branch assignment
- Assigned role
- Module permissions
- Temporary permission overrides

---

# Authentication Architecture

User identity shall be managed through Supabase Authentication.

Authentication features:

- Secure password hashing
- Session tokens
- Password recovery
- Multi-device login
- Multi-factor authentication (future support)

The application database shall never store plain text passwords.

---

# Users Table

Table: users

Purpose:

Stores the identity profile of every person using the ERP.

Fields:

- id (UUID, Primary Key)
- auth_user_id (Supabase Auth User ID)
- company_id (Foreign Key)
- employee_id (optional reference)
- first_name
- middle_name
- last_name
- display_name
- email
- mobile_number
- profile_photo_url
- preferred_language
- account_status

Account Status Values:

- Pending Approval
- Active
- Suspended
- Locked
- Archived

Audit Fields:

- created_at
- created_by
- updated_at
- updated_by

---

# Roles Table

Table: roles

Purpose:

Defines available roles within the ERP.

Examples:

Global Roles:

- Developer
- Owner
- Co-Owner
- General Manager
- Corporate Accountant

Branch Roles:

- Branch Supervisor
- Operator
- Worker
- Local Staff

Fields:

- id
- role_name
- role_scope
  - Global
  - Branch
- description
- active_status

# Permissions Table

Table: permissions

Purpose:

Defines individual system capabilities.

Examples:

Inventory:

- inventory.view
- inventory.create
- inventory.edit
- inventory.approve
- inventory.delete


Accounting:

- accounting.view
- accounting.post
- accounting.approve


Human Resources:

- employee.view
- employee.edit
- payroll.view
- payroll.approve


Administration:

- branch.create
- user.manage
- permission.manage


Fields:

- id
- permission_code
- module
- description

---

# Role Permissions Relationship

Table: role_permissions

Purpose:

Connects roles to system permissions.

Example:

Branch Supervisor:

Allowed:

- inventory.view
- inventory.edit
- production.create

Not Allowed:

- branch.create
- company.manage


Fields:

- role_id
- permission_id

---

# User Branch Role Assignment

Table: user_branch_roles

Purpose:

Allows a user to hold different roles in different branches.


Example:

Juan Dela Cruz:

Siargao Branch:
- Branch Supervisor


Cebu Branch:
- Worker


Fields:

- id
- user_id
- company_id
- branch_id
- role_id
- assigned_by
- assigned_date
- expiration_date (optional)
- active_status

---

# Permission Override System

The system supports temporary or special permissions.

Example:

A Branch Supervisor may receive temporary authority to approve payroll during the absence of a manager.


Table: user_permission_overrides


Fields:

- id
- user_id
- permission_id
- granted_by
- start_date
- expiration_date
- reason
- active_status

---

# Access Evaluation Order

Whenever a user attempts an action, the system evaluates:

User Identity
        ↓
Company Access
        ↓
Branch Access
        ↓
Role Assignment
        ↓
Permission Check
        ↓
Temporary Overrides
        ↓
Allow or Deny

---

# Security Enforcement

Permissions shall be validated in:

- User interface
- API requests
- Supabase Row Level Security policies

The database shall always be the final authority.

---

# Architecture Rule

No user shall receive access simply because they exist in the system.

Every action must be authorized based on:

- Company
- Branch
- Role
- Permission
- Account status
