# 20.22 Journal Entries and General Ledger

## Purpose

The Journal and General Ledger system records all financial transactions using double-entry accounting.

Every financial event must maintain a balanced debit and credit relationship.

---

# Double Entry Rule

Every transaction requires:

Total Debits = Total Credits

No unbalanced journal entry shall be posted.

---

# Journal Entries Table

Table: journal_entries


Fields:

- id (UUID)
- company_id
- branch_id
- journal_number
- transaction_date
- reference_type
- reference_id
- description
- status

Status:

- Draft
- Pending Approval
- Posted
- Reversed

Audit:

- created_by
- approved_by
- created_at
- posted_at

---

# Journal Lines Table

Table: journal_lines


Fields:

- id
- journal_entry_id
- account_id
- debit_amount
- credit_amount
- description

---

# Source Transaction Integration

Journal entries may originate from:

- Purchase Receiving
- Inventory Adjustment
- Payroll Processing
- Sales Invoice
- Cash Transactions
- Asset Acquisition
- Depreciation
- Loan Payments

---

# General Ledger

The General Ledger is generated from posted journal entries.

The system shall provide:

- Account balances
- Transaction history
- Trial balance
- Financial statements

---

# Branch Accounting

Each journal entry records:

- company_id
- branch_id

This allows:

- Branch profit analysis
- Company-wide consolidation
- Multi-branch financial reporting

---

# Reversal Policy

Posted entries shall never be deleted.

Corrections shall be made using:

- Reversing entries
- Adjustment entries

The original financial history must remain intact.

---

# Architecture Rule

No financial event shall directly change account balances.

All financial changes must flow through journal entries.
