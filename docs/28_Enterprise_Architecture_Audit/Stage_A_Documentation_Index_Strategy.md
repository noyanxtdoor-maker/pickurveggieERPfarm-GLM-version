# Stage A (A6) — Documentation Index & Link-Integrity Strategy

**Type:** Remediation deliverable (Stage A · A6) · governing strategy
**Status:** Strategy defined; generated index produced; static manifests deprecated
**Date of record:** 2026-06-20
**Branch:** `architecture-audit`
**Resolves:** audit findings P0-01 (root manifest covers ~13%), P0-02 (fragmented manifest strategy), P2-04 (no link-integrity check)

This document defines how PickUrVeggie ERP V3 documentation completeness and link integrity are maintained, replacing the abandoned, hand-maintained `MANIFEST.json` approach.

---

## 1. Principle: the filesystem tree is the single source of truth

Documentation completeness is **not** tracked by a hand-edited manifest (which drifted to ~13% coverage — P0-01). Instead:

- The `docs/` tree itself is authoritative for "what documents exist."
- A **generated** index ([`docs/INDEX.md`](../INDEX.md)) is produced *from* the tree and committed, so the index can never silently diverge from reality.
- The static `MANIFEST.json` files are **deprecated** (see §4).

## 2. Generated index — `docs/INDEX.md`

`docs/INDEX.md` is an auto-generated listing of every Markdown file under `docs/`, grouped by section, with relative links. It carries an explicit "AUTO-GENERATED — do not edit by hand" header. It was generated in Stage A and should be **regenerated by CI** on every change (see §3).

**Regeneration (reference implementation — to be wired into CI, not committed as app code):**
```bash
# enumerate tracked docs and emit grouped markdown to docs/INDEX.md
git ls-files 'docs/*.md' | grep -v '^docs/INDEX.md$' | \
  awk -F/ '{sec=$2; print}' | sort   # (the Stage A generator script produced INDEX.md from this set)
```
The canonical generator used in Stage A groups by top-level section and writes relative links. CI should run an equivalent generator and **fail the build if the committed `INDEX.md` differs from a fresh generation** (i.e. someone added a doc without regenerating).

## 3. CI checks (strategy — to be implemented as CI configuration in a later, non-docs change)

Two checks, both reusing logic the audit already exercised:

1. **Index freshness check** — regenerate `INDEX.md` in CI; fail if it differs from the committed file. Guarantees the index always matches the tree (closes P0-01/P0-02 permanently).
2. **Internal link-integrity check** — scan every `docs/**/*.md` for relative Markdown links and fail on any broken target (the Phase 2 audit scanner is the reference implementation). Closes P2-04 and prevents link rot when files are renamed (e.g. the Stage A renames in A7).

> These checks are **CI configuration / tooling**, not application source code. They are intentionally **not** added in this docs-only Stage A change; they are specified here so a later infrastructure change can implement them. (Honors the "docs only" constraint of this stage.)

| `docs/12_Integration_Architecture/MANIFEST.json` | Section 12 | **Deprecated** → `INDEX.md` |
| `docs/13_Project_Status/MANIFEST.json` | Section 13 | **Deprecated** → `INDEX.md` |

The files are retained (not deleted) with a deprecation marker so history and any external references degrade gracefully. They may be removed entirely once CI generation is in place.
