# Entity Relationship Master Map

## Purpose

This document defines the fundamental entities and relationships of PickUrVeggie ERP V3.

The objective is to ensure:

- No duplicate records
- No conflicting data ownership
- Clear relationships between modules
- Long-term scalability
- Multi-company support
- Complete audit traceability

---

# Global Identity System

## Philosophy

Every record inside PickUrVeggie ERP V3 has two identities:

1. Internal System ID
2. Human Readable Reference Number

---

## Internal System ID

The database uses globally unique identifiers (UUID).

Example:

e8b4f5a1-8d32-4ac1-94fd-123456789abc

Purpose:

- Prevent duplicate records
- Allow synchronization between devices
- Support offline creation
- Enable global uniqueness

Users normally do not see this value.

---

## Human Readable Reference Number

Examples:

Employee:
EMP-2026-00001

Inventory Item:
INV-2026-00001

Purchase Order:
PO-2026-00001

Sales Order:
SO-2026-00001

Harvest Batch:
HARV-2026-00001

Purpose:

- Easier searching
- Printed documents
- Communication between employees
- Customer and supplier references

---

# Company Entity

## Purpose

The Company is the highest ownership level in the ERP.

All business records belong to a company.

---

## Company Contains

- Farms
- Users
- Employees
- Inventory
- Customers
- Suppliers
- Sales
- Purchases
- Accounting records
- Equipment
- IoT devices
- AI records
- Files and documents

---

## Multi-Company Architecture

A single user may belong to multiple companies.

Example:

Arlie

↓

SmartIsland AgriTech Farm

↓

Operations Role


The same person may also belong to:

Another Farm Company

↓

Consultant Role

---

# Company Isolation Rule

Data from one company must never be visible to another company unless explicitly shared.

Example:

Company A inventory

❌ Cannot be viewed by Company B

Company A financial reports

❌ Cannot be viewed by Company B

---

# User Entity

## Purpose

A User represents an account that can access the system.

Examples:

- Owner
- Employee
- Accountant
- Consultant
- External future users

---

# User Properties

A User contains:

- Login credentials
- Personal profile
- Authentication methods
- Security settings
- Trusted devices
- Notification preferences
- Language preferences
- Timezone preferences

---

# User Relationship

A User may belong to:

One or more Companies

A User may have:

One or more Roles

A User may access:

Different workspaces depending on permissions.

---

# Employee Entity

## Purpose

An Employee represents a person who performs work for a company.

Examples:

- Farm workers
- Supervisors
- Operators
- Managers
- Accountants

---

# User vs Employee Rule

This is a critical ERP rule.

A User is not always an Employee.

Examples:

External consultant:

User

↓

No employee record

---

Farm worker:

User

↓

Employee record

---

# Employee Information

Employee stores:

- Employee number
- Personal details
- Employment status
- Position
- Department
- Salary structure
- Work history
- Attendance records
- Payroll records
- Assigned tasks

---

# Employee Lifecycle Rule

Employees are never permanently deleted.

When an employee leaves:

Keep:

- Employee history
- Attendance records
- Payroll history
- Work history

Deactivate:

- Login account
- Mobile access
- Trusted devices

---

# Roles and Permissions

## Philosophy

Roles describe responsibilities.

Permissions control actions.

A role does not automatically grant unlimited authority.

---

## Example Roles

- Developer
- Owner
- Co-owner
- Administrator
- Accountant
- Supervisor
- Operator
- Worker

---

# Multi-Role Support

A person may have multiple roles.

Examples:

Juan

Farm A:
Worker

Farm Nursery:
Supervisor

---

Permissions are determined by:

- Company
- Farm
- Department
- Location
- Assigned responsibility

---

# Permission Matrix Principle

Permissions are controlled by individual actions.

Examples:

Can View Inventory:
Yes / No

Can Approve Payroll:
Yes / No

Can Edit Accounting:
Yes / No

Can Override Inventory Limits:
Yes / No

---

# Workspace Entity

## Purpose

A workspace controls the active environment of a user.

A user may switch between:

- Companies
- Farms
- Departments
- Personal workspace

---

# Personal Workspace

Every user receives a private workspace.

Examples:

- Personal notes
- Personal calendar
- Personal reminders
- Personal task views
- Personal preferences

Personal workspace data belongs to the individual user.

---

# Device Entity

## Purpose

A device represents a trusted method of accessing PickUrVeggie ERP.

Examples:

- Android phone
- iPhone
- Tablet
- Desktop browser

---

# Device Information

The system records:

- Device ID
- Device type
- Operating system
- App version
- First registration date
- Last active date
- Security status

---

# Device Trust Status

A device may be:

Trusted

The device can access ERP data.

---

Restricted

The device has limited access or requires verification.

---

Revoked

The device cannot access company information.

---

# Device Security Rules

A device does not own the data.

The company owns operational data.

The user owns personal preferences.

The device only receives temporary authorized access.

---

# Audit Identity Chain

Every important action must answer:

Who performed it?

↓

Which company did it belong to?

↓

Which user account was used?

↓

Which device was used?

↓

What record was changed?

↓

When did it happen?

---

# Final Identity Principle

Identity is the foundation of trust.

Before the system can record a crop, inventory movement, salary, or financial transaction, it must know:

Who performed the action,

under which company,

with what permission,

using which authorized device.
