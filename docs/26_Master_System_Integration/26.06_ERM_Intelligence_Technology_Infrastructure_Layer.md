# Intelligence, Technology and System Infrastructure Entity Relationship Layer

## Purpose

This layer represents the digital nervous system of PickUrVeggie ERP V3.

It connects:

- Codex AI intelligence
- IoT sensors
- Mobile devices
- Files and documents
- Notifications
- Audit records
- Offline synchronization
- Security and data lifecycle management

This layer ensures that information flows securely between humans, devices, and the ERP.

---

# Codex AI Entity

## Purpose

Codex is the intelligence companion of PickUrVeggie ERP V3.

Codex does not own data.

Codex reads authorized information, analyzes patterns, and provides recommendations.

---

# Codex Data Sources

Codex can analyze:

- Production records
- Crop history
- Inventory movements
- Sales performance
- Financial reports
- Employee productivity
- Equipment history
- IoT sensor history
- Historical trends
- SOP knowledge base

---

# Codex Request Records

Every AI interaction stores:

- Request ID
- User requesting assistance
- Date and time
- Related ERP module
- Context information
- AI response
- Confidence level (when applicable)
- Source of information

---

# AI Data Classification

Codex must distinguish between:

## ERP Facts

Examples:

- "Eggplant Tunnel A produced 500 kg last month."
- "Inventory of Calcium Nitrate is 25 kg."

These are retrieved from ERP records.

---

## AI Knowledge

Examples:

- Pest treatment suggestions
- General agricultural advice
- Best practices

These are generated using AI knowledge.

---

## AI Authority Limits

Codex may:

- Explain information
- Analyze patterns
- Create drafts
- Recommend actions
- Generate reports

Codex cannot:

- Approve payroll
- Move money
- Delete records
- Change financial history
- Override permissions
- Perform critical actions without approval

---

# Mobile Device Entity

## Purpose

---

# Device Records

Stores:

- Device ID

- Application version
- Trust status
- Last synchronization
- Security status

---

# Device Trust States

Examples:

Trusted:

Normal access is allowed.

---

Restricted:

Additional verification or limited access is required.

---

Revoked:

Access is blocked and company data is removed according to policy.

---

# Offline Synchronization Queue Entity

## Purpose

Allows farm operations to continue without internet.

---

# Offline Queue Records

Stores:

- Queue ID
- User
- Device
- Action performed
- Related record
- Creation time
- Synchronization status
- Error details
- Conflict status

---

# Synchronization Status

Examples:

Pending

Waiting for internet connection.

---

Processing

Currently being synchronized.

---

Completed

Successfully stored in ERP.

---

Conflict

Requires human review.

---

Failed

Synchronization failed and requires correction.

## Purpose

Stores documents, images, and evidence related to ERP records.

---

# File Types

Business Documents:

---

# File Records

Each attachment stores:

- File type
- File size

- Upload date

# Storage Lifecycle Policy

Critical documents:

- Stored permanently

Operational media:

- Compressed

- Automatically archived or deleted after expiration

# Audit Log Entity

## Purpose

The audit log is the permanent memory of system activity.

---

# Audit Records

Every important event records:

- Who performed the action
- What action occurred
- Which record changed
- Previous value
- New value
- Date and time
- Device used
- Location information (when permitted)

---

# Audit Integrity Rule

Audit records cannot be modified or deleted by normal users.

Only controlled system-level maintenance may archive old logs.

---

# Backup and Data Lifecycle

## Purpose

Ensures long-term reliability and ownership of company information.

---

# Data Storage Strategy

Primary System:

Supabase Database

---

Backup Systems:

- Google Drive backup repository
- Exportable reports
- Database backup files

---

# Data Portability Rule

The company must always be able to export and recover its information.

No single service provider should permanently lock the company data.
