# Inventory and Supply Chain Entity Relationship Layer

## Purpose

Inventory is one of the most sensitive components of an ERP.

A small mistake in inventory affects:

- Production records
- Cost calculations
- Purchasing decisions
- Sales availability
- Financial statements

Therefore, every movement of inventory must be traceable.

---

# Inventory Architecture Philosophy

Inventory does not simply represent "how many items exist."

The ERP must answer:

- What item is it?
- Where did it come from?
- When was it received?
- Which batch does it belong to?
- How much remains?
- Where was it used?
- Who used it?
- What was the financial impact?

---

# Inventory Entity Hierarchy

The inventory structure follows:

# Inventory Item Master Entity

## Purpose

The inventory item master is the permanent library of all items the company uses.

An item should only be created once.

## Inventory Item Records

Each item stores:

- Item ID

- Item name
- Category

- Preferred supplier

- Current average cost

- Maximum stock level

# Unit Conversion System

The ERP supports multiple units.

Example:

Calcium Nitrate:

Purchase unit:
Kilogram

Usage unit:
Gram

Conversion:

1 kilogram = 1,000 grams

---

## Conversion Rules

The system stores:

- Base unit
- Conversion ratio
- Allowed measurement units

All calculations are converted into a standard base unit.

- Supplier

- Expiration date

---

# FIFO Inventory Rule

Default inventory costing follows:

First In

↓

First Out

The oldest available batch is consumed first.

---

## Example

Inventory:

Batch A:
10 kg

Batch B:
20 kg

Consumption:

15 kg

Result:

Batch A:
0 kg

Batch B:
15 kg remaining

---

# Inventory Movement Ledger

## Purpose

The movement ledger is the permanent history of all inventory changes.

Inventory quantity should never be manually edited without creating a movement record.

---

# Movement Types

Incoming:

- Purchase receiving
- Production return
- Transfer received
- Adjustment increase

---

Outgoing:

- Crop consumption
- Sales
- Waste
- Expired materials
- Transfer out
- Adjustment decrease

---

# Movement Records

Each movement stores:

- Movement ID
- Date and time
- Inventory item
- Batch affected
- Quantity
- Unit
- Before quantity
- After quantity
- Related document
- User performing the action
- Reason

---

# Inventory Adjustment Rules

## Normal Users

Cannot create unrestricted adjustments.

---

## Authorized Users

May adjust inventory only with:

- Proper permission
- Required explanation
- Approval if required
- Complete audit record

---

# Negative Inventory Policy

The system should prevent inventory from becoming negative.

---

## Exception Override

Authorized users may override the restriction.

Requirements:

- Permission
- Reason
- Approval workflow
- Audit trail

# Final Inventory Principle

Inventory is not a number.

It is a complete history of every item from purchase, storage, usage, and final financial impact.

If the ERP cannot explain where a kilogram of fertilizer came from and where it went, the inventory system has failed.
