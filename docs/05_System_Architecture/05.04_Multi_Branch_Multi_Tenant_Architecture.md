# 05.04 Multi-Branch Multi-Tenant Architecture

## Purpose

PickUrVeggie ERP V3 is designed as an enterprise agricultural ERP platform capable of supporting a single company operating multiple independent branches, farms, warehouses, stores, and operational locations.

Each branch must maintain complete data separation while allowing authorized corporate users to access consolidated company-wide information.

---

# Organizational Hierarchy

The system follows the hierarchy:

Company
│
├── Branch / Location
│   │
│   ├── Farm Zones
│   ├── Inventory
│   ├── Crop Production
│   ├── Employees
│   ├── Payroll
│   ├── Sales
│   ├── Expenses
│   ├── Equipment
│   ├── Assets
│   └── Daily Operations
│
└── Corporate Management

---

# Branch Data Isolation Principle

Every operational record must belong to:

- Company
- Branch

Examples:

- Inventory belongs to a specific branch
- Employees belong to a specific branch
- Payroll belongs to a specific branch
- Sales transactions belong to a specific branch
- Production records belong to a specific branch
- Equipment and assets belong to a specific branch

No branch user shall be able to view, modify, export, or delete records belonging to another branch unless explicitly granted cross-branch authority.

---

# User Access Model

## Global Roles

These users can access all branches:

- Developer
- Owner
- Co-Owner
- General Manager
- Corporate Accountant

Capabilities:

- View all branches
- Switch branch dashboards
- View consolidated reports
- Manage branches
- Assign branch personnel

Additional restrictions:

Corporate Accountant may access company-wide financial records and reports but shall not automatically receive authority over operational management, employee administration, or inventory control unless explicitly granted additional permissions.

---

## Branch Roles

These users are restricted to their assigned branches.

Examples:

- Branch Supervisor
- Operator
- Worker
- Local Staff

Capabilities:

- Perform daily branch operations
- Manage assigned records
- View branch reports according to their permissions

Restrictions:

- Cannot access other branch data
- Cannot switch to unauthorized branch dashboards

---

# Branch Dashboard Filtering

Users with global access shall have a branch selector.

Example:

View Dashboard:

[ All Branches ▼ ]

Options:

- All Branches
- Siargao Farm
- Cebu Farm
- Bohol Farm

Branch users shall automatically be limited to their assigned branches.

If a user has multiple branch assignments, only those authorized branches shall appear in the selection list.

---

# Database Architecture Requirements

Every operational table shall include:

- company_id
- branch_id
- created_by
- created_at
- updated_by
- updated_at

Examples:

Inventory:
- company_id
- branch_id

Sales:
- company_id
- branch_id

Employees:
- company_id
- branch_id

Crop Production:
- company_id
- branch_id

Equipment:
- company_id
- branch_id

Branch identifiers shall never be freely editable by ordinary users after a transaction has been created.

Moving inventory, assets, employees, or operational ownership between branches shall require a formal transfer workflow with complete approval records and audit history.

---

# User Branch Assignment Model

Users shall not be directly tied to a single branch.

The system must support situations where one person manages or works across multiple branches.

Example:

Regional Manager:

- Siargao Branch
- Cebu Branch
- Bohol Branch

This shall be handled using a user_branch_roles relationship.

---

# Branch Assignment and Login Policy

## Branch Assignment Authority

Users shall not be allowed to freely select or register themselves into any branch.

Branch access shall only be assigned by authorized users such as:

- Developer
- Owner
- Co-Owner
- General Manager
- Authorized HR Administrators

The assignment process shall define:

- Which branches a user can access
- The role of the user within each branch
- The date the assignment became active
- The person who approved the assignment

---

## Single Branch User Experience

If a user is assigned to only one branch:

Example:

Employee Juan Dela Cruz

Assigned Branch:

- Siargao Farm

Upon login, the system shall automatically enter the assigned branch dashboard.

No branch selection screen shall be displayed.

---

## Multi-Branch User Experience

If a user is assigned to multiple branches:

Example:

Employee Juan Dela Cruz

Assigned Branches:

- Siargao Farm
- Cebu Farm

After login, the user shall be presented with a branch selection screen containing only authorized branches.

Example:

Select Working Branch:

[ Siargao Farm ▼ ]
[ Cebu Farm ▼ ]

The user shall never be able to view or select branches outside their assignments.

---

# Branch-Specific Roles

A user may have different roles in different branches.

Example:

Juan Dela Cruz

Siargao Branch:
- Branch Supervisor

Cebu Branch:
- Worker

Therefore, permissions shall not be attached only to the user.

Permissions shall always be evaluated based on:

- User identity
- Current active branch
- Assigned role within that branch

---

# User Branch Role Relationship

The system shall implement a relationship similar to:

user_branch_roles

Fields:

- id
- user_id
- branch_id
- role_id
- assigned_by
- assigned_date
- active_status

This structure allows:

- One user to manage multiple branches
- Different roles per branch
- Temporary assignments
- Historical access tracking
- Enterprise-level security and auditing

---

# Security Enforcement

Branch security shall be enforced at multiple levels.

## Application Layer

The user interface shall display only information that the current user is authorized to access.

## Database Layer

Supabase Row Level Security (RLS) shall enforce branch-level data separation.

A branch user attempting to query another branch's records shall receive zero results.

The database shall remain the final authority for security, even if the application interface fails.

---

# Accounting Consolidation Principle

Financial records shall be recorded separately per branch.

Example:

Siargao Branch Profit:
₱850,000

Cebu Branch Profit:
₱600,000

Corporate Dashboard:

Total Company Profit:
₱1,450,000

The system shall support:

- Individual branch financial reports
- Consolidated company financial statements
- Branch profitability comparisons

---

# Inventory and Asset Separation Principle

Inventory, equipment, and assets shall never be mixed between branches.

Example:

Branch: Siargao

Calcium Nitrate:
50 kg

Branch: Cebu

Calcium Nitrate:
20 kg

Transfers between branches shall be recorded as formal transfer transactions with approval workflows and complete audit history.

---

# Future Scalability Requirement

The architecture must support:

- One company with hundreds of branches
- Multiple farms per branch
- Multiple warehouses per branch
- Multiple stores per branch
- Thousands of employees
- Millions of operational records

No module shall be developed assuming a single-branch environment.

---

# Architecture Rule

Multi-branch isolation is a mandatory system-wide rule.

All future database schemas, APIs, user interfaces, reports, AI systems, IoT integrations, and mobile applications must respect company and branch boundaries.

No future development shall bypass branch isolation requirements.
