# 27.04 Deprecated Code Replacement Plan

## Purpose

This document identifies existing V2 components, patterns, and technologies that are not compatible with the long-term PickUrVeggie ERP V3 architecture.

The objective is not to remove everything immediately.

Every replacement shall follow a controlled migration strategy that protects existing functionality.

---

# Replacement Philosophy

The V2 system contains valuable business knowledge.

Therefore, the rule is:

KEEP BUSINESS LOGIC.

REPLACE ARCHITECTURAL LIMITATIONS.

---

# Authentication System Replacement

## Current V2 Implementation

Current approach:

- Local user accounts
- Passwords stored locally
- Local session storage
- Basic role checking

Status:

🔴 Must be replaced.

---

## V3 Target Implementation

Replacement:

- Supabase Authentication
- Secure password handling
- JWT session management
- Multi-device login management
- Enterprise RBAC integration

---

# Migration Safety Rules

The following rules are mandatory:

1. No working V2 feature shall be removed until the V3 replacement is complete and tested.

2. Every replacement must include:
   - Migration strategy
   - Data migration plan
   - Security review
   - Testing validation

3. Business workflows shall always take priority over code cleanliness.

4. Architectural decisions must follow the official documentation in `/docs`.

# Final Principle

PickUrVeggie ERP V3 is an evolution of V2.

The existing application is the foundation.

The migration strategy is:

Preserve what creates business value.

Replace what prevents enterprise scalability.

Upgrade everything in a controlled and tested manner.
